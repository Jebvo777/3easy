# Серверный ПЛАН 16 октября

Три решения используют текущий заказ, его технологию и ресурсы паспорта. Крой/комплектация хранит цвета, размеры, готовые комплекты, раскладки, предел слоёв, доступность материала и время с основанием. Автопредложение настилов — эвристика по потребности, не САПР лекал. Можно менять слои, разделять и объединять совместимые настилы.

Целое изделие закрепляет пачку за человеком с необходимыми навыками. Узлы организуют группы и допускают отдельного исполнителя. Поток распределяет неделимые операции по совместимым местам. Ручное размещение операций, блока или выбранных операций меняет тот же черновик. Координаты схемы отделены от назначения и не создают мощности. Возможны отмена, повтор и сравнение вариантов.

Сервер считает пачки, зависимости, конечные ресурсы и людей по общему портфелю, сменам и перерывам. Готовность настила ограничивает запуск следующих операций. Подготовка учитывается для пачки/настила, время не заменяется нулём. Незнакомое время и неполная комплектация не дают полного прогноза. Количественные связи операций остаются 1:1 внутри готового комплекта.

Сохранение создаёт ревизию рабочего пространства и заказа. Расчёт создаёт неизменяемую версию; мастер → технолог → начальник → публикация. Снимок включает три решения, технологию, расписание, людей, ресурсы и допущения. Прежние факты не переписываются; начатая пачка сохраняет цепь. У прежнего запуска без идентичности пачек сохраняется целиком старая цепь. Состав технологии с фактом не заменяется: доступна независимая копия в новой цели.

ДЕЙСТВИЕ использует общий компонент карты поверх реальных опубликованных заданий. Место раскрывает операции, партии, исполнителя и факт; запись выпуска и ОТК проходит прежние серверные проверки. Повторная приёмка того же объёма отклоняется. Экономика распознаёт принятый объём по исходному объёму заказа, а не ошибочно по размеру каждой пачки.

Это реализация согласованного контура на текущем PHP-хранилище. Не заявлены геометрическая оптимизация раскроя, самостоятельное обучение LLM и точный глобальный оптимум. Промежуточные проверки не выполнялись по указанию владельца; базовая проверка после публикации всех этапов.
