# EASY3 7.2.1 — вход в наполненное демо

Причина пустого рабочего стола: SQL наполнил существующую учебную фабрику, но `demo_enter` при каждом входе создавал другую компанию с тремя начальными целями. После отделения подготовки от пошива старый стартовый сценарий также не создавал план: готовность комплектации оставалась неизвестной.

Вход находит только явно отмеченную SQL-наполнением синтетическую фабрику версии `easy3-demo-q4-20261023-v2`. Создаёт отдельную рабочую копию её целей, подготовки, распределений, планов, заданий, событий и экономики. Идентификаторы компании, записей и учебных аккаунтов создаются заново; ссылки в JSON, ключах объектов, зависимостях и согласованиях заменяются. Последняя версия получает хеш входов своей копии. Секреты, чужие аккаунты, AI-задания и документы не копируются. Исходная фабрика не изменяется. Вставка выполняется небольшими пакетами в одной транзакции.

При открытии прежнего нетронутого демо с тремя стандартными целями без плана, фактов и правок интерфейс автоматически открывает наполненную копию. Прежняя компания остаётся в БД. В остальных малых демо есть явная кнопка «Открыть наполненное демо». Обычные компании не переключаются автоматически. Загрузка сопровождается окном, повторные клики объединяются в один запрос.

Если большого шаблона в БД нет, начальное маленькое демо теперь явно содержит учебный факт готовности компонентов и основание включённой стоимости. ОТК и подтверждение затрат относятся к одной демонстрационной партии. При смене предприятия период финансового обзора возвращается к полному портфелю.

Для присланной уже наполненной БД новое изменение схемы и повторный импорт наполнения не нужны: заменить файлы сайта и перезагрузить страницу. Все четыре прежние конфигурации входят только в частную поставку без изменения. Сборка сохраняется вместе с исходниками.

По прямому указанию пользователя проверки, тесты, линтеры и запуск приложения для этой правки не выполнялись. Прежний QA-отчёт относится к выпуску 7.2 и не подтверждает изменения 7.2.1.
