# Генерация технологической последовательности

## Протокол

EASY3 использует серверный адаптер Artemox `https://api.artemox.com/v1/chat/completions`, Bearer и те же модели, что приложенный нейрочат. Только описание изделия и технические особенности входят во внешний запрос. Компания, заказчик, участники, ставки, цены, история и внутренние UUID не передаются. Ключ находится в отдельном частном `config.ai.local.php`, не в JS и не в GitHub.

Результат — JSON с версией схемы, допущениями, вопросами и 1–50 операциями. Операция включает код, название, тип центра, зависимости, предполагаемое оборудование/разряд и оценку времени либо null. Сервер ограничивает поля, длины, числовые диапазоны, число операций, ссылки, циклы и единственный финальный выход. Ответ не является кодом и не исполняется.

## Применение

Генерация сохраняет предложение отдельно от цели и опубликованного плана. Пользователь смотрит список и применяет его в локальный черновик. Нормы остаются незаполненными, пока человек не проверит оценки или не внесёт свои данные. Затем сохраняется обычная ревизия технологии; расчёт, согласование и публикация выполняются привычным процессом. Повтор запроса с тем же ключом возвращает прежнее предложение, не повторяя платный вызов.

## Происхождение

Исходный механизм: приложенный проект `app/ai.php`, функции `ai_gateway_chat`, `ai_gateway_models`, `ai_normalize_model`. Фактические настройки прочитаны из предоставленного SQL; первичная инструкция подтверждает endpoint и заголовок. Платёжный документ API не использован для AI. Самые ранние демки EASY3 служат ориентиром состава технологической операции, а не доказательством промышленной нормативной базы.

Контракт и правила приёмки будут дополнены после реализации и финальной проверки.
