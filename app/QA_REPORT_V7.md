Серверные сценарии используют настоящие обработчики, сессию, права, идемпотентность, календарь и экономику с изолированным SQLite-адаптером. Из MySQL установщика берутся определения таблиц, для SQLite адаптируются только служебные SQL-выражения. Рабочая БД и её реквизиты в этих сценариях не используются. Проверено: отдельное предприятие создаётся один раз; исходное не меняется; неизвестные расходы не превращаются в нули; оптимизация не пересекает людей/центры, закрепляет начатую работу, не увеличивает просрочку при включённой защите и создаёт только новый черновик. Этот черновик проходит прежние три согласования и публикацию. Новый факт блокирует применение устаревшего расчёта; чужие компания, цель и план закрыты; работник получает только свои задания.

В аналитике проверены конечные операции, повторный ОТК, предыдущий равный период, перерывы смены и неоднозначные старые события. В Excel проверены 15 колонок образца, типизированные значения, пустое неизвестное время, закрепление заголовков и реальные SVG/PNG из общих координат. Полный пакет содержит 14 листов. Отдельные JSON и SVG технологии сохранены.

Найдены и исправлены: переход регулярного выражения имён через границу строк; распознавание ФИО в Excel с адресами ячеек; повторные запросы БД при построчном скрытии личных данных; узкий заголовок Excel. Границы бюджета и цена без убытка используют целочисленное деление. В старой финансовой проверке исправлен неполный контрольный снимок: у конечной операции отсутствовал is_final, из-за чего база ошибочно считалась несопоставимой; бизнес-формулы не менялись.

Живые запросы использовали только вымышленные технические данные и числовые агрегаты. Ответы gpt-6-luna получены за 17,70 / 10,66 / 9,57 / 9,05 секунды; каждый проверен enterpriseReply или insightReply. Повторившаяся группа людей в ответе предприятия удаляется локальным объединением частей. Ключ не включён в журнал, тестовые данные или публичную поставку.

Ограничения проверки: DOM-сценарии используют контрольный API и Happy DOM, без рисования GPU и фактического течения CSS-анимации. Бинарник Chromium в окружении отсутствует, полноценные снимки приложения не получены. Happy DOM неверно проверяет десятичный шаг денежных полей; в соответствующем тесте только ограничение step заменено на any, серверная проверка копеек остаётся настоящей. Проверка OOXML подтверждает формат и чтение; запуск настольного Microsoft Excel не выполнялся. Визуальный считыватель отображает некоторые даты серийными числами, openpyxl подтверждает правильные значения datetime и форматы дат. Прямой прогон на MySQL 5.7/MariaDB и пользовательском хостинге не выполнялся. Это не отчёт о нагрузочном тестировании или гарантия точности AI для произвольного документа.

Для обновления с v6.2 SQL не требуется: используются существующие таблицы и JSON-поля. Приватный архив сохраняет исходные example-конфигурации побайтно и их local-копии; публичный содержит только очищенные примеры.
