# Обновление EASY3 от 16 октября 2026

1. Сделайте резервную копию файлов и БД.
2. Импортируйте database/update_20261016.sql в текущую БД system404_easy3 через phpMyAdmin. Миграция MySQL 5.7+ теперь состоит из прямых CREATE TABLE IF NOT EXISTS без CHECK, PREPARE и сессионных переменных. Новые служебные таблицы создаются без внешних ключей к старым таблицам с другой кодировкой; существующие связи не удаляются. Сервер проверяет ссылки и доступ к данным. Скрипт повторяемый: добавляет AI-хранилище, черновики и версии ПЛАНА, метаданные пачек. Заказы, пользователи, факты и прежние планы не удаляются. Полный install.sql используется только для новой учебной установки.
3. Замените файлы приложения содержимым нового архива целиком. index.php лежит в корне. Публичный установочный ZIP не содержит config.local.php и config.ai.local.php: сохраните эти файлы на сервере. Если AI-конфигурации ещё нет, скопируйте config.ai.example.php в config.ai.local.php и укажите прежний ключ Artemox. Если используете отдельно подготовленный частный архив с конфигурациями, при собственных изменениях подключения сохраните свою версию. Не публикуйте частные конфигурации.
4. Откройте сайт обычным способом. Сборка использует новые хеши JS/CSS и очистку HTTP-кеша, сохраняя cookie. На хостинге не нужны Node.js, Composer и внешние CDN.
5. Для AI нужны PHP 8.2+ с cURL, JSON и PDO MySQL, HTTPS и исходящие HTTPS-запросы к api.artemox.com. Новая технология строится частями с сохранением прогресса.

В ПЛАНЕ откройте технологию, создайте AI-черновик или копию образца, проверьте время и сохраните. В КРОЕ задайте размеры/цвета, готовые комплекты или настилы. Выберите организацию и распределите работы в ЦЕХЕ. Подтверждение создаёт версию портфеля; после согласований опубликованные задания появляются в ДЕЙСТВИИ.

Действующая технология с производственным фактом сохраняется. Для изменения её состава используйте независимую копию в новой цели. Карта будущей работы и новые публикации не стирают старые факты. Три формы организации используют реальные навыки паспорта; отсутствие универсального исполнителя или специальной машины показывается как ограничение.

В этой поставке app/lib/schema.php при первом обращении к БД добавляет только отсутствующие request_json/job_json/lease_token/lease_until/call_count в ai_generations и planning_meta в tasks. Проверка выполняется через SHOW COLUMNS; повторный запуск и одновременные первые запросы не создают дубли полей. Данные не перекодируются. Сначала примените SQL, затем загрузите все файлы архива с сохранением своих частных конфигураций. Node.js на хостинге не требуется.
