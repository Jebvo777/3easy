# Обновление EASY3 v7.1

При обновлении с v7 или v6.2 SQL не требуется. Данные, сроки и опубликованные планы не изменяются. Замените файлы сайта содержимым архива; приватные конфигурации включены в частную поставку. У существующих AI-заданий адаптивный интервал появится после следующего ограничения частоты. Далее сохранена инструкция предыдущих поставок.

# Обновление EASY3 до v7

1. Сохраните резервную копию существующей БД system404_easy3 и файлов сайта.
2. При обновлении с v6.2 новый SQL не нужен: используются существующие таблицы и JSON-поля. Если установлена более ранняя версия, импортируйте прежний database/update_20261017_61.sql целиком через phpMyAdmin в существующую БД. Скрипт повторяемый: создаёт только недостающие служебные таблицы и освобождает просроченные аренды. В нём нет PREPARE, CHECK, новых внешних ключей, удаления или перекодировки старых таблиц. Отсутствующие дополнительные поля прежних версий по-прежнему добавляет серверный слой schema.php. database/install.sql используется исключительно для новой учебной установки.
3. Загрузите всё содержимое ZIP в корень сайта. Не переносите только отдельные JS: manifest.json, исходники и готовые ресурсы должны относиться к одной поставке.
4. Частный архив владельца включает прежние реквизиты в config.example.php/config.ai.example.php и дублирует их в local-файлах. Повторный ввод не нужен. Если настройки изменились на хостинге после отправки исходных файлов, сохраните более новые local-файлы. Публичный архив GitHub реквизитов не содержит.
5. Требуются PHP 8.2+, PDO MySQL, cURL, JSON, sessions, DOM/XML, zlib, iconv и mbstring; MySQL 5.7+ или MariaDB. Загрузка документов: upload_max_filesize от 12M, post_max_size от 16M; storage/imports доступен PHP для записи и закрыт от HTTP. Для Nginx перенесите правила из tools/nginx.example.conf, включая запрет vendor и storage.
6. Откройте приложение. Новый хеш ресурсов обновляет HTTP-кеш без удаления входа и бизнес-данных. В незавершённой генерации нажмите «Продолжить». Модель и ключ задаются сервером; браузер их не получает.
7. Для приёмки пройдите один сквозной сценарий: цель из документа → проверка условий → технология и подтверждение времени → комплектация → план и согласование → частичный выпуск → ОТК → прогноз. Прогноз и AI-симуляция сохраняют гипотезы отдельно от опубликованных планов.

В поставке включены новое видео высокого разрешения, номенклатура, девять технических примеров и локальные библиотеки чтения документов. Composer/Node/Python/OCR на хостинге не нужны. Неподтверждённые AI-оценки не становятся нормами автоматически; экономический охват и неизвестные суммы остаются видимыми.

В v6.1 новых столбцов нет: контуры и подтверждённые параметры цели хранятся в имеющихся JSON-полях. Скрипт совместимости можно повторно выполнить и поверх v6. Незавершённые старые генерации сохраняют прогресс. Финальная проверка описана в QA_REPORT_V61.md.

В v6.2 увеличена петля на главной, сводка стала компактнее. AI-подбор показывает отдельное окно ожидания. Контуры изделия больше не пересоздаются при обновлении статуса и остаются полностью нарисованными.

В v7 появились импорт предприятия, оптимизация, потенциал экономики цели, аналитика периода и Excel-экспорты. Загрузите всю поставку, включая новый lib/xlsx.php и файлы новых модулей. Никакие планы не публикуются автоматически.
