# Обновление EASY3 до v3

Эта версия меняет интерфейс и сохраняет структуру/цеха в существующих JSON-полях. **Новая SQL-миграция для v3 не нужна**, если установлен предыдущий архив v2 и его `003_upgrade_20261011.sql`.

1. Сохранить обычную резервную копию файлов и БД.
2. Заменить файлы из нового архива целиком, включая `index.php`, `lib/`, `assets/manifest.json`, `assets/runtime/`, `assets/media/` и `.htaccess`. Не смешивать каталоги разных выпусков. Сохранить свой `config.local.php`, если настройки хостинга менялись.
3. Перезагрузить обычную вкладку. HTML получает `no-store`; при смене сборки сервер передаёт `Clear-Site-Data: "cache"`. Cookie и сохранённые данные не очищаются. CSS и весь JavaScript используют новые имена с хешем, включая вложенные модули. Режим инкогнито не требуется.
4. Для уже существующей компании открыть «Паспорт → Команда», добавить роли/бригады/цеха и сохранить. Старые люди, факты, цели и опубликованные планы сохраняются; руководители не придумываются автоматически. Новая кнопка «Открыть демо» создаёт актуальный учебный пример с полной структурой.

Если версия v2 ещё не устанавливалась и таблицы `economy_observations` нет, один раз импортировать прежний `database/003_upgrade_20261011.sql`. Это прежняя миграция подтверждений затрат, не новая миграция структуры. Она безопасна для повторного запуска и не наполняет действующие предприятия вымышленными фактами.

**Не импортировать `database/install.sql` или `002_seed.sql` в действующую БД для обновления.** Эти файлы предназначены для отдельной новой учебной установки.

Цеха хранятся в `companies.passport.structure`, роли/принадлежность — рядом с человеком, принадлежность ресурса — рядом с центром, карты цехов — в `companies.layout.workshops`. Старый корневой layout совместим с первым цехом. Сохранение одного цеха сохраняет другие карты. Смена состава создаёт ревизию; опубликованные снимки сохраняют историческую структуру.

На Nginx применять ограничения из `tools/nginx.example.conf`. При использовании внешнего кеша хостинга HTML/PHP не должен кешироваться; уникальные имена статических ресурсов остаются работоспособны и с CDN.
