# Проверки EASY3

Выполнять только на отдельной учебной БД: HTTP-сценарии создают компании, пользователей, планы и факты. Они не очищают чужие данные. Приложению в рабочем хостинге эти зависимости не нужны.

Из корня `app/`:

```sh
php tools/qa/engine_checks.php
php tools/qa/finance_checks.php
python -m pip install requests
python tools/qa/integration.py http://127.0.0.1:8099
python tools/qa/organization_checks.py http://127.0.0.1:8099 tools/qa/output
python tools/qa/cache_checks.py http://127.0.0.1:8099 tools/qa/output
cd tools/qa
npm install
cd ../..
node tools/qa/ui_checks.mjs tools/qa/output/state.json
node tools/qa/team_ui_checks.mjs tools/qa/output/state.json
node tools/qa/organization_model_checks.mjs tools/qa/output/state.json
node tools/qa/model_checks.mjs
TZ=Europe/Moscow node tools/qa/refinement_checks.mjs
```

PHP-приложение должно быть запущено отдельно с доступом к установленной тестовой БД. HTTP-проверка создаёт `tools/qa/output/state.json` для DOM-проверки. Этот снимок содержит тестовые имена и адреса; не публиковать его. Второй аргумент HTTP-проверки задаёт каталог результата; UI принимает путь к снимку и необязательный каталог результата, модель — каталог результата.

DOM-harness проверяет действия, формы, переходы и отсутствие WebGL, но не растеризацию, освещение, типографику и реальную работу перетаскивания в браузере. Проверка геометрии проверяет вершины, индексы, UV, замкнутость и реальное изменение геометрии при разрыве. Она не заменяет GPU-проверку изображения.

Результат поставки: [QA_REPORT.md](../../QA_REPORT.md).

`install_checks.php` создаёт временную БД только на локальном QA-сервере и удаляет её после проверки. Пример: `EASY3_QA_DSN='mysql:host=127.0.0.1;port=3307;charset=utf8mb4' EASY3_QA_USER=root php tools/qa/install_checks.php`. Сценарий не читает частную конфигурацию приложения. `organization_checks.py` проверяет отдельные цеха, связи структуры, сохранность истории и права; `cache_checks.py` проверяет HTTP-заголовки, содержимое сборки и локальные ресурсы. Карта команды проверяется через DOM и отдельную модель, а не графическую растеризацию.

Новая проверка финансового охвата проверяет неизменность базы, неизвестные затраты и сопоставимость объёмов. Проверка доработки проверяет расстановку, навыки, автосвязи, календарные интервалы и отдельные карты материала. Для SQL-обновления импортировать миграцию дважды в копию БД предыдущей версии и сравнить количества старых сущностей; новая таблица должна остаться пустой. Полный `install.sql` проверять отдельно на новой учебной БД.

## v6.1: только после публикации реализации и сборки

- `php tools/qa/v61_contracts.php`: даты/подтверждение цели, прогноз, контракты контуров и сохранение результата. Создаёт вымышленные контрольные данные в `tools/qa/output/v61`.
- `npm ci --prefix tools/qa`, затем `node tools/qa/v61_ui_checks.mjs`: действия интерфейса с контрольным API, блокировка повторов, навигация, таблица и схема изделия. Это DOM-проверка, не браузерный снимок.
- `node tools/qa/v61_avatar_checks.mjs`: конечные координаты, габариты двенадцати вариантов людей и ограничение количества отрисовок.

Запускать из `app`. Боевые конфигурации, внешняя БД и реальный AI для этих трёх проверок не требуются. Живой запрос к настроенному провайдеру выполнялся отдельно только с вымышленным техническим описанием.

## v6.2: только после публикации реализации и сборки

После `v61_contracts.php` запустить `node tools/qa/v62_ui_checks.mjs`. Сценарии проверяют компактную главную на трёх ширинах, одно окно AI и его неизменную анимацию, прогресс, завершение/ошибку, паузу/продолжение/закрытие/уход, непрерывность подключения SVG изделия и непрерывный цикл контуров v7. Полный браузерный кадр и течение CSS-анимации в GPU-рендерере этим не проверяются.


## v7: финальные проверки

После публикации всех этапов и сборки: `php tools/qa/v61_contracts.php`, затем `php tools/qa/v7_integration.php`. Второй сценарий создаёт изолированную SQLite БД в памяти из определений установщика, не читает приватные конфигурации и не подключается к рабочей БД. Нужны PDO SQLite и zlib. После него `node tools/qa/v7_ui_checks.mjs` и `python3 tools/qa/v7_xlsx_checks.py` (openpyxl и Pillow только для разработки). Дополнительная регрессия: v61/v62 UI, engine_checks.php, finance_checks.php, model_checks.mjs, refinement_checks.mjs, v61_avatar_checks.mjs. Сценарии пишут только вымышленные данные в исключённую из поставки папку output. Живые ответы AI проверяются отдельно теми же контрактами; ключи не записываются в результаты. Подробности и ограничения — QA_REPORT_V7.md.
