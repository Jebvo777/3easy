# EASY3 — PHP-демо швейного производства

Премиальное рабочее пространство: короткий лендинг → вход/регистрация → компания → паспорт → ЦЕЛЬ → ПЛАН → ПРОИЗВОДСТВО. Предприятие сначала показывает людей, руководство, бригады и цеха; оборудование редактируется внутри выбранного цеха. Один вход `index.php`, остальные файлы — независимые модули и локальные ресурсы. Демо не требует Composer, Node.js или CDN на хостинге.

## Установка на m21.system404-design.ru

Требования: PHP 8.2+ с `pdo_mysql`, sessions, JSON; MySQL 8 или MariaDB 10.6+; HTTPS. Подходит обычный PHP-хостинг Apache/Nginx.

1. Распаковать содержимое каталога `app/` в корень сайта. В готовом установочном ZIP `index.php` уже находится на верхнем уровне.
2. Для новой учебной установки создать/открыть БД `system404_easy3` и импортировать `database/install.sql` через phpMyAdmin. Этот файл создаёт таблицы и вымышленные тестовые данные. Для обновления действующей БД использовать только [UPGRADE.md](UPGRADE.md). Отдельно предоставлены `001_schema.sql` и `002_seed.sql`.
3. В архиве уже подготовлен частный `config.local.php`. В GitHub его нет: скопировать `config.example.php` и указать пароль самостоятельно или передать `EASY3_DB_PASSWORD`. Подключение: `localhost`, база и пользователь `system404_easy3`.
4. Открыть `https://m21.system404-design.ru/`. Кнопка «Открыть демо» создаст отдельный тестовый сеанс с актуальными датами и своим предприятием.

Альтернатива импорту: `php tools/install.php`. Установщик работает только из CLI. Статический SQL-план имеет даты сборки; новый демо-сеанс формирует свежий календарь.

На Nginx закрыть доступ к `/lib/`, `/database/`, `/tools/`, `/storage/`, файлам `config.*.php`, SQL и документации. Для Apache правила `.htaccess` включены. Пример Nginx находится в `tools/nginx.example.conf`.

## Сквозной сценарий

1. Открыть демо: рабочий стол, часы, живая петля, сигнал и переход к причине. «Показать разрыв» включает только визуальный пример, не записывает простой.
2. В паспорте добавить человека, навык, центр и смену. Заполненность 5/5 не блокирует первый заказ.
3. В ЦЕЛИ создать заказ для себя или заказчика; цена, объём, срок, принадлежность материала и прямые статьи. Открыть состав и ограничения прогноза.
4. В предприятии посмотреть карту людей, руководства, бригад и цехов. Открыть нужный цех, затем добавить/перенести/повернуть рабочие центры и соединить поток. «По паспорту» расставляет центры выбранного цеха; «Люди по навыкам» распределяет его команду; «Связать поток» использует сохранённую технологию. Сохранить расстановку. Колесо — масштаб, правая кнопка — перемещение камеры, левая — вращение. Центр можно перемещать; R — поворот, стрелки — шаг 0,5 м, Delete — убрать с карты, Ctrl/Cmd+Z — отмена, Ctrl/Cmd+S — сохранить. Без WebGL автоматически открывается работающая схема.
5. В ПЛАНЕ собрать ручную технологию новой цели либо применить обозначенный учебный шаблон. Сохранить. Рассчитать весь портфель, сравнить порядок по сроку/коротким заказам. Мастер → технолог → начальник согласуют одну основу; собственник в демо может пройти все этапы. Опубликовать задания.
6. В ПРОИЗВОДСТВЕ начать доступное задание, записать часть выпуска, передать её дальше. На конечной операции ОТК распределяет проверенный объём на годное, доработку и брак. «Доработка выполнена» → «Повторная проверка» гасит остаток, не удваивая выпуск.

## Что реализовано

PHP/PDO-хранилище, вход/регистрация, несколько компаний, серверные роли, CSRF, ревизии, идемпотентные команды, ручной паспорт и цели, 3D-редактор расстановки, технологический DAG, совместный календарь людей/центров со сменами и перерывами, две стратегии, согласование, публикация, события и баланс ОТК. Производственная экономика считается PHP-движком; закрытые суммы не отправляются другим ролям.

Петля — закрытые металлические 3D-меши с фасками, PBR-текстурой, локальным окружением и анимированными потоками. Разрыв меняет настоящую геометрию. Предприятие также создаётся из 3D-геометрии. Логотип сохранён из демки; фон создан ImageGen. Three.js включён локально с MIT-лицензией. Учитывается уменьшение движения и отсутствие WebGL.

## Честные границы демо

- Нейросети, Excel/документы, автоматическое построение технологии и AI-советы — **«В разработке»**. Файлы никуда не отправляются.
- Учебные нормы не являются нормативами предприятия. Эвристика не доказывает оптимальность. Календарь планирует весь объём операции; сохранённая передаточная партия пока не ускоряет расписание. Зависимости количественно 1:1; склад и поступления не моделируются, материал предполагается готовым.
- Область экономики — производство; общие расходы распределяются по нормированным трудочасам. OWN не показывает прибыль будущей продажи. CONTRACT показывает прогноз, без учёта банковских поступлений. Состав и неизвестные расходы видны.
- Публикации неизменяемы. Новая публикация заменяет только нетронутые задания; начатые и фактические закреплены. В демо технология опубликованного заказа закреплена. Промышленное перепланирование с изменением технологии и фактом, фото/QR, шифрование персональных полей, полноценный офлайн и исправление событий не имитируются.
- Команда паспорта не создаёт автоматически аккаунты работников. Тестовый аккаунт работника связан с учебным исполнителем `p-sew-1`; промышленное управление членством требует отдельного модуля.
- Производственные данные вымышленные. Демо не объявляется готовым промышленным внедрением.

## Модули

| Файлы | Назначение |
|---|---|
| index.php, lib/bootstrap.php, lib/api.php | HTTP-вход, доступ и выдача разрешённых данных |
| lib/modules/ | Предметные серверные команды |
| lib/engine.php | DAG, календарь, расчёт, публикация |
| lib/seed.php | Актуальное учебное предприятие для каждого демо-сеанса |
| assets/js/ | Самостоятельные UI-модули, петля и объёмный цех |
| assets/css/app.css, refinement.css | Слои дизайн-системы, контраст и размещение в экране |
| assets/vendor/ | Локальный Three.js с лицензией |
| database/ | Схема, наполнение, единый SQL установки |
| tools/ | CLI-установка и примеры сервера |

Все ресурсы локальные. Подключение БД хранится в частной конфигурации; API не возвращает пароль и не печатает подробности SQL в ответ.

## Обновление предыдущей версии

Для установленной v2 новая SQL-миграция не нужна; инструкция — [UPGRADE.md](UPGRADE.md). `database/003_upgrade_20261011.sql` требуется только более старой установке, где отсутствует таблица подтверждений затрат. Существующие факты не заменяются тестовым наполнением. Ожидание, факт, отклонение и прогноз доступны на рабочем столе собственника; подтверждение затрат сохраняет отдельную неизменяемую версию с указанным основанием.
