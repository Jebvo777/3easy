# EASY3 / 3easy

**EASY3 — премиальный продукт для проектирования производства и принятия понятных решений. Главное — не ERP.**

Человек задаёт цель, собирает производство в визуальном конструкторе, проверяет варианты, запускает согласованный план и видит, как реальные события меняют срок и экономику. Расчёты, ограничения, нормативы и обработка данных находятся в движке. Интерфейс показывает ситуацию, причину и следующий шаг.

Планка качества — macOS: спокойная композиция, ясная иерархия, аккуратная типографика, последовательные действия и детали по запросу. Красивый фон или прозрачные панели сами по себе этой планки не достигают.

## Текущий статус

Это база знаний и проектирования, собранная из предоставленных материалов. Документы, SQL и демки не означают наличие готового серверного продукта, работающего оптимизатора или обученной нейросети. Различия между требованием, поведением прототипа и инженерным предложением отмечены явно.

Первая проверка — на реальном предприятии; ядро должно оставаться применимым к разным видам производства. Полный цикл: **ЦЕЛЬ → ПЛАН → ДЕЙСТВИЕ → факт и ОТК → прогноз и экономика → решение → новая версия**.

Обязательные опоры: несколько компаний и заказов, ресурсы и календари, нормы с источниками, версии и согласования, частичный выпуск и передача партий, контроль качества, пересчёт по факту, сценарии и AI-помощник. Полноценная бухгалтерия, кадровый документооборот и CRM не определяют продукт.

## Как пользоваться контекстом

Последнее прямое указание владельца проекта имеет приоритет перед старой демкой и прежним ответом чата. Не переносить в разработку ограничения прототипов: обязательный паспорт 5/5, вход сразу в единственный заказ, фиктивную авторизацию через переключатель роли или расчёт по одной универсальной норме.

Вопросы, требующие данных пилота, перечислены [отдельно](docs/DECISIONS_AND_QUESTIONS.md). Они не дают оснований самовольно сокращать заявленный объём. Сообщения коммитов — обезличенные, например: `Добавлено описание конструктора, изменены критерии проверки`.

Проверки целостности пакета и арифметики прототипа: [отчёт контекста](docs/verification-report.json), [отчёт TargetModel](docs/target-model-verification.json). Проверки воспроизводятся через `python tools/verify_context.py` и `node tools/verify_target_model.cjs`; они не заменяют приёмку рабочего продукта.
